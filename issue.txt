4. MODULE 04: ATTENDANCE & BIOMETRIC TIME TRACKING
====================================================================================================
Screens Involved: AttendanceView, BiometricLogsView, ShiftManagementView

A. FIELD-BY-FIELD AUDIT & CLOCK-IN DEFICIENCIES:
- Clock-In / Clock-Out Action:
  * Current Issue: Web clock-in allows infinite consecutive "Clock In" clicks if state does not immediately lock. Clock-out does not prompt for shift wrap-up summary or tasks completed.
  * Required Logic: State machine must enforce: (Logged Out -> Clocked In -> On Break -> Resumed -> Clocked Out). Once Clocked Out, re-clocking on same day should either be blocked or flagged as "Second Shift / Overtime".
- Break Tracker (Tea Break / Lunch Break):
  * Current Issue: Starting a break does not pause the productive working hours counter; break duration has no alerts even if break exceeds 120 minutes.
  * Required Logic: Active work timer freezes during break; separate "Break Duration" timer increments; automated alert if break exceeds policy limit (e.g. 60 mins).
- Regularization Request Modal:
  * Reason for Regularization: Free-text field has no minimum character limit (user can type "." and submit).
  * Missed Punch Type: Dropdown must clearly specify: "Missed Clock-In", "Missed Clock-Out", or "Both".
  * Supporting Proof: File attachment input lacks MIME-type and file size validation (accepts dangerous .exe, .sh files or oversized images).

B. LOGICAL RULES & BUSINESS EDGE CASES:
- Midnight / Overnight Shift Edge Case (e.g. 21:00 to 06:00 next day):
  * Issue: Attendance system resets daily records strictly at 00:00:00 midnight. If an employee clocks in at 22:00 on Monday and clocks out at 06:00 on Tuesday, the system records an unclosed Monday record and creates an incomplete Tuesday record.
  * Logic Needed: Shift-based day association: The attendance record must attach to the Shift Date (Monday), regardless of crossing the 00:00 calendar date boundary.
- Half-Day vs Full-Day Attendance Thresholds:
  * Issue: Total work hours < 4 hours is currently recorded as "Present" if the employee clocked in and out.
  * Logic Needed: Business rule automation:
    * Work Hours >= 8 hours -> Full Day Present
    * 4 hours <= Work Hours < 8 hours -> Half Day Present (flags deduction of 0.5 Day Leave or Loss of Pay)
    * Work Hours < 4 hours -> Marked as Absent / Loss of Pay (LOP) unless approved regularization exists.
- Geo-Fencing & IP Whitelisting:
  * Issue: Remote employees and on-premise office employees use the same clock-in without location verification.
  * Logic Needed: Optional GPS coordinates capture or corporate Wi-Fi IP validation to mark punch as "Office Verified" vs "Remote Unverified".

C. UI/UX & USER PERSPECTIVE DEFICIENCIES:
- Monthly Attendance Calendar Grid does not visually highlight public holidays, weekends, approved leaves, and unauthorized absences with distinct color-coded chips.
- Total hours format displays raw decimals (e.g., 8.43 hours) instead of user-friendly time format (e.g., "8h 26m").
- No visual progress bar towards the required 40-hour weekly quota.

Severity: CRITICAL | Priority: HIGH

B. LOGICAL RULES & BUSINESS EDGE CASES:
- Negative Balance Prevention:
  * Issue: If an employee has 1.0 Casual Leave balance and applies for 3.0 days, system allows submission and sets balance to -2.0 without routing to "Loss of Pay / Unpaid Leave".
  * Logic Needed: Validate available balance against requested working days. If requested days > balance, system must split the leave or convert the excess into "Unpaid Leave (Loss of Pay)".
- Sandwich Leave Policy Calculation:
  * Issue: If an employee takes Friday off and Monday off, the intervening Saturday and Sunday are excluded by default.
  * Logic Needed: Configurable Sandwich Policy: If company policy treats intervening weekends/holidays as leave days when flanked by leaves, system must compute 4 days total leave instead of 2 days.
- Team Staffing Conflict & Blackout Dates:
  * Issue: Multiple members of the same critical project can book leaves simultaneously during key release periods.
  * Logic Needed: System must warn the manager if >30% of the team is already on approved leave for the same date window; block leave booking on company-wide Blackout Dates unless approved by HR Admin.
- Leave Cancellation Logic:
  * Issue: Once approved, an employee cannot cancel an upcoming leave if their plans change, or cancelling does not credit back the deducted leave balance.
  * Logic Needed: "Request Cancellation" button on approved future leaves; manager one-click approval restores the exact balance automatically.

C. UI/UX & USER PERSPECTIVE DEFICIENCIES:
- Balance Cards (Sick, Casual, Earned) do not show "Accrued", "Consumed", "Pending Approval", and "Remaining Balance".
- Calendar preview does not show company holidays when selecting leave dates, making users guess which days are already off.

18. SYSTEM-WIDE CROSS-CUTTING GAPS & ARCHITECTURAL VULNERABILITIES
====================================================================================================

1. DYNAMIC DATA INTEGRITY & REFERENTIAL CONSISTENCY:
- Hard-coded Fallback Mocks: Multiple frontend views still contain fallback mock arrays that mask backend API failures. If an API returns an empty array [], the UI displays fake mock people or fake tasks instead of genuine empty states.
- Missing Soft-Deletes: Deleting an employee, project, or department risks cascade-deleting historical attendance, payslips, and audit logs. All core entities must implement an isDeleted: boolean flag with deletedAt timestamp.

2. INPUT SANITIZATION & CROSS-SITE SCRIPTING (XSS):
- Rich text and broadcast descriptions render raw HTML in several components without DOMPurify sanitization, opening risks for script injection via internal webmail or announcements.

3. REAL-TIME EVENT SYNCHRONIZATION (WEBSOCKETS):
- Socket.io is initialized in the server, but frontend views rely on manual page reloads to see new leave applications, task assignments, and webmail messages. Client components must subscribe to dynamic socket events (e.g., "leave:applied", "mail:received", "attendance:clocked").

4. MOBILE RESPONSIVENESS & BREAKPOINTS:
- Multi-column tables (Attendance calendar, Weekly Timesheets, Payroll breakdown) overflow horizontally on tablet and mobile viewports (< 768px) without card-based responsive transforms.

5. ERROR HANDLING & USER RECOVERY:
- Server 500 errors display generic toast messages ("An error occurred") without actionable troubleshooting hints or error correlation IDs that the user can report to the IT helpdesk.

====================================================================================================

A. EMAIL SERVICE PROVIDER (SMTP / SENDGRID / RESEND / AWS SES):

  * No external email delivery engine (e.g., Nodemailer, SendGrid, Resend, AWS SES) is configured in `package.json`.

  * Password Reset Links cannot reach the employee's actual external email inbox (e.g. Gmail / Outlook).

  * Required Logic: Integration of standard SMTP / transactional email service with HTML email templates for:
    1. Welcome Email + Password Setup Link
    2. Leave Status Updates (Approved/Rejected)
    3. Monthly Payslip PDF dispatch
    4. Security Alerts (Failed login attempts, Account Lockout)

B. CLOUD OBJECT STORAGE (AWS S3 / CLOUDINARY / GOOGLE CLOUD STORAGE):
- Current State:
  * File uploads (Resumes, Policies, Avatars, Medical certificates) use `multer` and store files directly on the local server disk filesystem.
- Gaps & Missing Integrations:
  * If the server container restarts or scales horizontally across multiple instances, locally uploaded files become unreachable (broken image links and missing documents).
  * No file encryption at rest or virus scanning for uploaded candidate resumes and identity proofs.
  * Required Logic: Dedicated cloud storage adaptor (AWS S3 bucket / Cloudinary / MinIO) with pre-signed temporary URLs for sensitive payroll and identity documents.

- Current State:
  * Attendance is currently recorded solely via web browser clock-in/clock-out buttons.
- Gaps & Missing Integrations:
  * Real enterprise environments use physical biometric fingerprint / facial recognition turnstiles at office doors.
  * The backend currently lacks an automated webhook / machine push API endpoint (`/api/biometric/sync` or ADMS push protocol) to ingest biometric punch logs directly from hardware devices.
  * Required Logic: ADMS / IClock biometric listener endpoint that parses machine serial number, employee device ID, punch timestamp, and syncs automatically into the `Attendance` table.

- Gaps & Missing Integrations:
  * No direct bank payout integration (e.g. RazorpayX Payouts, Cashfree, or NEFT/RTGS NACH bank file export format like ICICI / HDFC / SBI bulk payment excel templates).
  * Required Logic: One-click "Disburse Salaries" API linking to banking payout gateway or automated generation of standard bank-compliant `.txt` / `.csv` bulk upload files for Corporate Net Banking.
